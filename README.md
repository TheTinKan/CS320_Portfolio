# CS320_Portfolio


I can ensure that my software is functional and secure by following the requirements, testing different scenarios, and checking how the program handles invalid information. Throughout this course, I used JUnit 5 to test the contact, task, and appointment services. I created tests for both valid and invalid inputs to make sure the classes worked as expected and rejected information that did not meet the requirements. I also tested the service methods to verify that objects could be added, updated, or deleted when appropriate. By validating inputs and limiting which fields could be changed, I helped protect the integrity of the data. Regular testing and reviewing code for potential issues are important parts of maintaining reliable and secure software.

I interpret user needs by reviewing the requirements and breaking them down into individual features that can be implemented and tested. For example, the customer required contact IDs to be unique, no longer than 10 characters, and unchangeable after creation. I incorporated these requirements by adding validation to the Contact class and checking for duplicate IDs in the ContactService class. I then created JUnit tests to verify that these requirements were being followed. Breaking the requirements into smaller tasks helped me stay organized and made it easier to determine whether the finished program met the customer's expectations.

When designing software, I prefer to start by understanding the requirements and determining what classes and methods will be necessary. I then break the project into smaller parts so I can focus on implementing and testing each component individually. During this course, I followed this approach by developing the object classes and service classes separately. I also used JUnit testing throughout development instead of waiting until the entire project was finished. When a test failed, I reviewed the related code, identified the problem, and made corrections before continuing. This approach helped me keep my code organized, find errors more easily, and build software that was easier to maintain.
